# 사용자 가이드

## 프로젝트와 데이터

프로젝트 생성 시 선택한 부모 폴더 아래 `llm-change-...` 작업 폴더가 생깁니다. `project.db`, `backups/`, `exports/`, `logs/`를 포함합니다. 데이터 폴더는 별도로 둡니다. 회사 NAS에서 허용된 데이터를 로컬로 복사한 뒤 사용하세요. 이 프로그램은 NAS에 로그인하거나 원본을 변경하지 않습니다.

Import는 train/val/test가 들어 있는 공통 상위 폴더를 선택합니다. 개별 split 폴더 선택은 지원하지 않습니다. 같은 내용의 다른 위치를 Import하면 root만 다시 연결됩니다. 원본 JSON/JPG 내용이 달라졌다면 기존 프로젝트를 유지하고 새 프로젝트에서 시작합니다.

품질 오류 목록은 데이터 · AI 분석 화면에 표시됩니다. split 누출, 중복 이미지, 잘못된 JSON, 누락된 이미지, orphan 이미지가 있으면 계획을 만들 수 없습니다. 라벨 구조가 누락된 JSON을 조용히 0으로 채우지 않습니다.

## OpenAI

기본 Provider는 mock입니다. 실제 OpenAI 호출을 하려면 provider를 openai로 선택하고 모델명, 현재 입력/출력 단가(USD/백만 토큰), 예상 비용 한도, API key를 입력합니다. API key는 화면 메모리에만 남으며 종료 후 다시 입력합니다. 환경변수 OPENAI_API_KEY도 지원하지만 `.env` 파일을 자동으로 읽지는 않습니다.

작업 생성만으로 비용이 발생하지 않습니다. 실행할 때 이미지 전송/유료 호출 확인 체크가 필요합니다. 모델·프롬프트 등 분석 설정이 다른 실험은 새 Run으로 기록합니다. ‘선택 작업 예산 변경’은 현재 작업의 누적 한도만 바꾸고 사유·시각·변경 전후 값을 기록합니다. 완료된 분석과 검수, 생성 당시 설정 해시는 유지됩니다. 현재 provider는 Chat Completions의 image input과 strict JSON schema를 지원하는 모델을 대상으로 합니다.

중단: 일시정지는 현재 API 요청이 끝난 뒤 적용됩니다. Resume은 pending만 처리합니다. failed를 다시 시도하려면 Retry 준비 후 Resume합니다. 취소 작업은 ‘재시도 · 중단 작업 복구’의 ‘취소 작업 다시 열기’로 명시적으로 일시정지 상태로 바꿉니다. 완료 결과는 보존하며 실패 항목은 재시도 준비가 필요합니다. 프로그램이 강제 종료되었으면 중단 작업 복구를 누릅니다. 불명확한 요청은 실패로 표시하며 재시도를 명시적으로 선택합니다. 처리 중인 요청이 정리되기 전에는 예산 변경·취소 작업 재개가 차단됩니다.

예산으로 멈춘 경우 작업을 새로 만들지 말고 해당 작업을 선택한 뒤 ‘선택 작업 예산 변경’에서 기존 사용액을 포함한 새 누적 한도와 사유를 입력하세요. 이어하기는 미완료 항목만 처리합니다. 실제 과금 여부가 불명확한 요청의 예약액은 지우지 않으며, 앱의 예상 한도는 API 서비스의 실제 청구 상한을 보장하지 않습니다.

## 이미지 검수

‘비교하고 검수하기’ 후 원본/AI/최종 라벨이 나란히 표시됩니다. ‘원본 유지’ 또는 ‘AI 라벨 적용’으로 초안을 고르거나 ‘직접 수정’으로 최종 체크박스를 수정합니다. 선택과 자동 저장은 완료 확정이 아닙니다. 원본과 AI 판단이 다르면 해당 행이 강조됩니다. AI 근거 요약은 기본으로 표시하며 ‘AI 판단 근거 · 검수 메모’에서 상세 근거를 봅니다. 세부 인공물이 선택되면 저장 시 상위 인공물도 켭니다. 신규 구축에서 제외된 도로 표식은 최종 체크를 사용할 수 없습니다.

상단의 전체·필수 검수 남음·완료·보류 수치는 필터와 관계없이 전체 작업을 기준으로 합니다. 필수 검수/미검수 목록에서는 저장한 완료 항목이 빠지고 다음 미완료 항목이 표시됩니다. 이미지 로딩에 실패하면 이전 이미지를 지우고 저장·초안 저장을 차단합니다. 파일을 복구하거나 데이터 경로를 다시 연결한 뒤 ‘새로고침’을 누르세요.

라벨을 바꾼 경우 한국어 근거가 있어야 완료 저장할 수 있습니다. 라벨·한국어 근거를 수정하면 이전 영문 입력을 비웁니다. 영문이 필요하면 선택 입력란에 새 설명을 작성하세요. 자동 번역 API는 호출하지 않습니다. 내보내기는 기존 영문 `reason`을 다른 판정에 재사용하지 않으며 영문 미입력 수를 품질 화면, `english_reason_missing`을 manifest에 표시합니다. 영문이 필수인 납품 규격이라면 누락 수를 0으로 맞춘 뒤 전달하세요. 원본 라벨·근거를 그대로 유지하는 검수는 원본 설명을 보존합니다.

- 휠: 확대/축소. 드래그: 이동. 두 시점이 동기화됩니다.
- 화면 맞춤 / 100% 버튼, 차이 영상, 깜박임을 제공합니다.
- Ctrl+S: 완료 저장. Ctrl+Enter: 완료 저장 후 다음.
- Alt+Left / Alt+Right: 이전/다음. F: 화면 맞춤. Ctrl+Z: 저장 전 수정 취소, 또는 이전 저장 상태를 순서대로 복원. 감사 이력은 삭제하지 않습니다.
- 자동 임시 저장은 DRAFT입니다. 나중에 완료 저장해야 Gate를 통과합니다.
- 보류는 DEFERRED로 저장되며 완료 수에 포함되지 않습니다.
- 미검수/보류/필수 검수 필터와 검수 이력을 제공합니다.

## 팀 교환과 백업

팀원에게 같은 작업의 **DB 백업**과 허용된 로컬 데이터 사본을 전달합니다. 팀원은 백업 복원 후 동일 데이터를 Import하여 자기 PC 경로로 다시 연결합니다. 각 PC DB를 동시에 공유하지 않습니다.

검수 ZIP에는 이미지나 API key가 들어가지 않습니다. project/plan/run fingerprint와 sample ID, reviewer, timestamp, SHA256이 기록됩니다. 같은 결과는 SAME, 처음 받는 결과는 NEW, 서로 다른 결과는 CONFLICT입니다. 충돌 해결에서 내 결과 유지 또는 가져온 결과 사용을 직접 선택합니다. 미해결 충돌은 최종 Export를 차단합니다.

프로젝트 백업은 DB만 포함합니다. 원본 데이터 사본을 별도로 유지해야 합니다. 복원은 기존 프로젝트를 덮어쓰지 않고 새 폴더를 만듭니다. ZIP/DB는 암호화되지 않습니다.

## 평가

GPT vs Human은 사람이 완료 저장한 항목에서 계산합니다. Golden Set을 고정하면 이후 검수가 바뀌어도 reference 라벨은 변하지 않습니다. 같은 Golden에 대해 모든 Run의 prompt hash와 모델/coverage/라벨별 지표를 비교합니다.

Baseline vs Retrained 평가에는 실제 변화탐지 모델의 예측값이 필요합니다. 모델 예측 JSON 템플릿을 생성하고 `predictions`의 모든 sample ID에 실제 라벨을 채운 뒤 각 모델 이름으로 가져옵니다. 템플릿의 0은 자리표시자이며 모델 결과가 아닙니다. 모델 훈련 자체는 이 도구가 수행하지 않습니다.

## 0.1.2 화면 안내

왼쪽 메뉴는 작업 공간 → 데이터 · AI 분석 → 이미지 검수 → 품질 · 내보내기 순서입니다. 팀 작업과 통계는 아래 그룹에 있습니다. 진한 청록색 버튼이 각 단계의 주요 작업입니다.

OpenAI를 선택하면 모델·API Key·단가 설정이 나타납니다. 프롬프트와 재시도/복구 기능은 이름이 표시된 펼침 메뉴에 있습니다. 처리 결과는 요약과 표로 보이며, 원문 JSON은 ‘상세 기록 보기’에서 확인할 수 있습니다. 내보내기 완료 후에는 ‘저장 폴더 열기’로 결과를 바로 열 수 있습니다.

작은 창에서는 페이지나 오른쪽 라벨·근거 패널을 스크롤할 수 있습니다. 검수 화면의 가운데 구분선을 드래그하면 이미지와 라벨 표의 폭을 조정할 수 있습니다. 버전은 왼쪽 아래에 표시됩니다. [미리보기](ui-refresh.md)
