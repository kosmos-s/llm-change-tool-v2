# 사용자 설명서 · 0.1.11

## 1. 시작과 버전

Windows Portable은 ZIP을 모두 풀고 `LLMChangeTool.exe`를 실행합니다. EXE와 `_internal`을 함께 유지하세요. 이 설명서의 기능(독립 판정 포함)을 사용하려면 실행 화면의 버전이 0.1.11인지 확인합니다. GitHub의 최신 배포판이 이전 버전이면 해당 버전의 Windows 빌드 결과를 사용해야 합니다.

프로젝트는 로컬 디스크에 만들고 원본 데이터 폴더와 분리합니다. 프로젝트 DB를 NAS 공유 경로에 두지 않습니다. 기존 프로젝트는 열 때 자동 백업 후 스키마 7로 전환합니다. 전환된 DB는 구버전 앱으로 열지 마세요. 원본 데이터는 별도로 보관합니다.

## 2. 데이터 등록과 대상 선정

`train/val/test`를 포함하는 공통 상위 폴더를 선택합니다. `dataset/{train,val,test}`, `errors/{train,val,test}` 등 출처를 함께 읽습니다. 논리적 샘플 1건은 T1·T2 영상과 JSON입니다. 두 시점이 합쳐진 combined 영상도 지원합니다.

등록 수, 고유 후보 수, 보류 수, 제외 수, 선정 가능 수를 구분하세요. 품질 확인 사항 수가 곧 실패 샘플 수는 아닙니다. 고유 후보는 디코딩된 RGB 영상 내용으로 묶으며 동일 영상의 라벨 충돌·불완전 중복·split 누수는 보류합니다. 짝이 없는 파일이나 손상·파싱 실패로 제외된 샘플을 본작업에 넣지 않습니다. 등록된 원본 파일이 이후 바뀌거나 계획이 변조되면 진행을 차단합니다.

시험용은 기본 50건이며 30/50/100 또는 직접 입력할 수 있습니다. 본작업은 고유 샘플 3,000건입니다. 각 split 1,000건은 기본 작업 배분이고 합계 3,000건 안에서 바꿀 수 있습니다. 원본의 split을 옮기거나 재분할하지 않습니다. 선정 전 「표본 미리보기」에서 수량과 보류 사유를 확인하세요.

같은 데이터를 다른 폴더로 복사한 경우 재등록으로 경로를 연결할 수 있습니다. 원본 내용이 바뀌었다면 기존 결과와 섞지 말고 새 프로젝트를 사용하세요.

회사 검수 안내의 `dataset`은 전체 데이터, `dataset_sample`은 일부 데이터입니다. 이번 작업은 승인된 `dataset_sample`을 선택하고, 두 폴더를 한 번에 등록하지 마세요. 압축 표본처럼 `dataset_sample/dataset`과 `dataset_sample/errors`가 함께 있으면 `dataset_sample`을 선택해 두 출처를 포함합니다. 특정 오류 폴더만 선택하면 전체 작업의 split·후보 수량을 확인할 수 없습니다.

Jupyter의 `/home/jovyan/bizdata/`는 서버 마운트 경로입니다. Windows에서는 탐색기로 접근 가능한 공유 폴더·연결 드라이브 또는 내려받은 로컬 복사본을 선택하세요. 폴더 접근과 이미지 읽기는 시험용 50건으로 먼저 확인합니다. NAS 로그인과 API Key 관리 기능은 앱에 추가하지 않습니다.

## 3. AI 분석

Mock은 합성 시험용이며 본작업의 실제 AI 성공으로 인정되지 않습니다. OpenAI에서는 모델·단가·예산과 API Key를 확인합니다. API Key는 화면 메모리에만 남으며 종료 후 다시 입력합니다. 환경변수 OPENAI_API_KEY도 지원하지만 .env를 자동으로 읽지는 않습니다.

작업 생성은 과금하지 않습니다. 실제 실행은 영상 전송·유료 호출 확인 후 시작합니다. 앱의 자동 단가는 버전에 포함된 값이며 실시간 조회가 아닙니다. 본작업 전에 공식 단가와 계정 권한을 확인하세요.

예약액은 요청 직전에 이미지 크기·모델·detail·프롬프트·응답 스키마·출력 한도로 계산합니다. 재시도에는 추가 예약이 필요합니다. 이미지 토큰 계산 규칙 미확인 모델은 「이미지 1장 토큰 예약」을 지정해야 하며 미입력 시 전송 전에 멈춥니다. 기존 작업은 「선택 작업 이미지 예약 변경」에서 추정 근거를 남기고 이어갈 수 있습니다. 이 값과 비용은 추정치이며 공급자 측 절대 과금 한도가 아닙니다.

처리 100%와 성공 100%는 다릅니다. 성공·실패·대기 건수를 확인하세요. 작업 종료 후 선택 목록의 상태도 갱신됩니다. 요청의 원격 결과·과금 여부가 미확정인 항목은 자동 재시도하지 않습니다. 실패 복구 기능은 오류 유형과 안전한 재시도 가능 여부를 확인한 뒤 사용하세요.

응답 거부·잘림·빈 응답을 구분합니다. 토큰 사용량이 확인된 실패는 비용 기록에 포함합니다. 요청 ID와 영상 준비·AI 요청 단계의 시간은 상세 진단 기록에 보관하며 API Key는 기록하지 않습니다. 예상 비용에는 캐시 할인 등 실제 청구와의 차이가 있을 수 있습니다.

## 4. 이미지 검수

기본 정책은 불일치와 낮은 신뢰도(기본 0.7 미만)를 필수 검수합니다. 이전 core 시험용 정책은 낮은 신뢰도만 있는 결과를 자동 유지할 수 있으므로 주의하세요. 본작업은 기존 core 작업도 낮은 신뢰도를 필수 검수합니다. 기존 결과와 완료 검수 이력은 유지합니다.

1. 「비교하고 검수하기」로 목록을 만듭니다.
2. 「이미지 검수」에서 **검수자 이름을 먼저 입력**합니다. 「이름 기억」은 선택 사항이며 공용 PC에서는 사용하지 마세요.
3. 두 시점과 원본·AI 라벨을 확인합니다. 원본 유지, AI 적용, 직접 수정은 아직 최종 완료가 아닙니다.
4. 수정한 라벨에는 한국어 판단 근거를 입력합니다. 영문 근거는 선택 사항입니다. 라벨·한국어 근거가 바뀌면 기존 영문은 비워 모순을 방지합니다.
5. **「저장 후 다음」**으로 현재 1건을 확정하고 진행합니다. 「저장」은 현재 항목에 머무릅니다.

자동 임시 저장은 초안입니다. 현재 항목 저장, 초안 저장, 전체 검수 완료는 서로 다릅니다. 같은 내용·검수자·상태를 반복 저장하면 기존 이력을 유지하고, 실제 변경은 새 이력으로 남깁니다. 되돌리기도 이력을 삭제하지 않습니다.

「기타 인공물」을 해제하면 최종 기타 설명을 내보내지 않습니다. 원본의 설명은 그대로 보존하며, 최종 JSON에서 기존 arti_other_detail은 빈 문자열로 저장합니다. 검수 화면에서도 최종 기타 설명을 확인할 수 있습니다.

필터에 따라 저장한 항목이 목록에서 빠질 수 있습니다. 마지막 항목 안내는 현재 목록의 끝이며 전체 작업 완료를 뜻하지 않습니다. 상단의 전체 완료·필수 검수 남음을 확인합니다. 이미지 읽기 실패나 저장 실패 때는 완료 처리와 다음 이동을 차단합니다.

### 독립 판정 (사람 정답 만들기)

평가용 사람 정답(Golden Set)은 원본이나 AI 라벨을 보기 전에 영상만으로 판정하는 것이 좋습니다. 상단의 **「독립 판정」**을 켜면:

- 원본·AI 열은 「숨김」으로 표시되고 AI 근거, 원본 기타 설명, 불일치 등 확인 신호도 숨깁니다. 「원본 유지」「AI 라벨 적용」은 사용할 수 없습니다.
- 최종 라벨은 **미확정**에서 시작합니다. 원본 라벨을 복사한 기존 초안도 보여주지 않으며, 현재 검수자 이름과 최신 비교 결과가 모두 일치하는 자신의 독립 판정 기록만 다시 표시합니다. 다른 검수자 또는 이전 결과의 판정은 숨깁니다.
- 모든 라벨을 변화/없음으로 정하고 **판정 근거를 항상 입력**해야 완료됩니다. 원본과 같은 판정이어도 근거가 필요합니다(원본 일치 여부가 드러나지 않도록).
- 저장 이력 되돌리기는 쓸 수 없고, 이력 창에도 현재 검수자의 최신 비교 결과에 해당하는 독립 판정 기록만 표시합니다. 수정은 라벨을 직접 고쳐 다시 저장하세요.
- 저장한 기록에는 독립 판정 표시가 남고, 상단 요약에 「독립 판정 완료」 수가 나옵니다. Golden Set을 고정하면 결과에 `blind_reviews`(독립 판정 건수)와 `all_blind`가 표시됩니다.
- 수정 중인 내용이 있으면 모드와 검수자 이름을 바꿀 수 없습니다. 먼저 저장한 뒤 바꾸세요. 처음에 이름을 비워두었다면 판정 후 이름을 입력해 저장할 수 있습니다. 이름은 입력을 마쳤을 때(Enter 또는 다른 칸 클릭) 반영되며, 입력하는 동안에는 자동 임시 저장을 멈춥니다. 저장 후 이름을 바꾸면 해당 검수자의 기록 또는 미확정 라벨이 표시되고 소요 시간도 새로 셉니다. 설정은 프로젝트별로 기억합니다.
- 한 항목의 정답은 **최신 완료 기록 하나**입니다. 다른 검수자가 이미 독립 판정한 항목은 진행 표시에 「다른 검수자」가 붙고 자동 임시 저장을 하지 않습니다. 저장하려 하면 확인 창이 뜨며, 계속하면 내 판정이 최신 기록이 되어 Golden Set에 쓰이고 이전 판정은 이력에만 남습니다. 「미검수 항목」 필터에는 이미 완료된 항목이 나오지 않으니, 검수자끼리 맡을 범위를 미리 나누세요.

이름은 로그인이 아닙니다. 다른 사람의 이름을 입력하면 그 사람의 판정이 보입니다. 이름별로 숨기는 것은 원본이나 앞사람 판정에 끌리지 않도록 돕는 장치이며 접근 통제가 아닙니다.

품질 확인 화면의 표본 목록 등 다른 화면에는 원본 라벨이 보일 수 있으니, 판정이 끝나기 전에는 열지 마세요. 원본 기타 설명은 숨겨지지만 「기타 인공물」을 변화로 판정하면 내보내기에서 원본 설명이 유지됩니다. 팀 검수 ZIP으로 가져온 기록은 독립 판정 표시가 유지되지 않습니다.

프로젝트·AI 작업·필터별 마지막 샘플 ID를 기억합니다. 다시 열면 해당 샘플이 아직 목록에 있는 경우 이어서 표시합니다. 이름은 기억 옵션을 켠 경우에만 저장합니다.

| 단축키 | 동작 |
| --- | --- |
| Ctrl+S | 현재 항목 저장 |
| Ctrl+Enter | 저장 후 다음 |
| Alt+← / Alt+→ | 이전 / 다음 |
| Ctrl+Z | 이전 검수 상태로 되돌리기 |
| Ctrl+F | 샘플 ID 또는 경로로 항목 찾기 |
| F | 두 영상 화면 맞춤 |

입력 중인 텍스트의 되돌리기·편집과 단축키를 혼동하지 않도록 버튼을 함께 확인하세요. 「도움말」에서 기준과 단축키를 볼 수 있습니다. 영상 캐시는 최대 3항목·64MiB이며 파일 크기·수정 시각이 바뀌면 다시 읽습니다. 차이 영상은 선택할 때 계산합니다.

## 5. 최종 검증·내보내기

모든 AI 오류, 필수 검수, 보류·초안·이전 결과의 검수, 팀 충돌을 해결한 뒤 최종 검증을 실행합니다. 검증 통과 후 별도 폴더로 내보냅니다. 원본 JPG/JSON을 덮어쓰지 않습니다.

Gate 통과는 모든 건을 사람이 검수했다는 뜻이 아닙니다. 화면의 사람 검수 완료/전체 건수와 manifest의 all_human_reviewed를 함께 확인하세요. Mock 통과나 라벨 비교 점수는 실제 AI 정확도 또는 회사 모델 재학습 성과를 입증하지 않습니다.

내보낸 결과가 회사 Jupyter 도구나 학습 코드에 자동 반영되는 것은 아닙니다. 담당자가 내보낸 폴더의 JSON 구조·split·수량을 확인하고 학습 입력 경로로 지정해야 합니다. 기존 도구의 저장 대상과 덮어쓰기 방식은 사용 안내만으로 확인되지 않으므로 별도로 확인합니다.

내보내기는 임시 폴더에서 파일을 준비한 뒤 원본 무결성과 검수 버전을 다시 확인합니다. 준비 중 검수가 바뀌면 완성본으로 게시하지 않고 재검증을 요구합니다. 출력의 manifest에서 pilot/production과 계획·모델·프롬프트·파일 정보를 확인할 수 있습니다.

## 6. train·val·test의 정확한 역할

| 분할 | 모델 학습에서의 역할 |
| --- | --- |
| train | 모델 가중치를 학습하는 데이터 |
| val | 학습 중 성능을 확인하고 설정·모델·프롬프트를 선택하는 검증 데이터 |
| test | 선택을 마친 뒤 최종 성능을 평가하는 별도 데이터 |

**val은 결과 파일이 아닙니다.** 세 폴더 모두 입력 데이터와 정답 라벨을 담습니다. 예측 결과는 모델이 별도로 생성합니다.

현재 앱은 이미지를 GPT에 보내 라벨을 만들고 사람이 검수하는 도구입니다. train 폴더에 넣는 것만으로 GPT가 학습되지 않습니다. 정제한 train을 회사의 변화탐지 모델 학습 코드에 넣고, val로 설정을 결정한 뒤, 고정된 test에서 기존 모델과 개선 모델을 비교해야 합니다. 이 도구는 모델 학습 자체를 실행하지 않습니다.

같은 지역의 유사 타일이나 같은 영상이 다른 split에 섞이지 않아야 합니다. test를 반복해서 보며 모델·프롬프트를 조정하면 최종 점수가 낙관적으로 될 수 있습니다. 데이터별 1,000건은 검수 작업량의 기본 배분이며 모델 학습에 보편적으로 최적인 비율이라는 뜻은 아닙니다.

## 7. 대표 F1과 재학습 전후 비교

「평가 · 고급 기능」을 펼치고 「통계 · 모델 평가」로 이동합니다.

- **검수 중 AI 점수:** 현황 새로고침. 검수 완료 항목에 한한 **부분 평가**입니다.
- **고정 기준의 AI 점수:** 검수 완료 → 「확정 검수를 기준으로 고정」 → 평가용 val/test → 「AI 작업별 평가 비교」.
- **기존·재학습 모델 점수:** 같은 평가 기준 세트 → 예측 양식 받기 → 실제 예측으로 값 채우기 → 모델 예측 각각 가져오기 → 평가 결과 비교. v2 양식의 null은 미입력입니다. 모든 값을 실제 예측 0/1로 채우고 prediction_status를 complete로 바꾸세요.

내부 **대표 점수는 변화 유무 F1**입니다. 인공물·나무·산림·농경지·수계 중 하나라도 변화가 있으면 영상 쌍 1건을 양성으로 보고 `2TP/(2TP+FP+FN)`을 계산합니다. 기존 주요 5개 라벨의 micro F1은 **보조 점수**로 유지합니다. 하위 라벨·도로 표식은 대표 점수에 중복 합산하지 않습니다. 두 점수는 의미가 다르며, 변화 유형까지 맞았는지는 보조·라벨별 점수를 함께 확인하세요.

「전후 비교 · 보고서 저장」은 동일 Golden Set의 두 모델만 비교합니다. JSON에 F1 차이와 %p 변화, CSV에 각 사례의 TP/FP/FN/TN·수정/새 오류를 저장합니다. 사람이 영상을 확인하고 CSV에 검토 기록을 남긴 뒤 「수동 집계 대조」로 숫자를 맞춰볼 수 있습니다. 검토표를 저장한 것만으로 사람 검수가 완료되지는 않습니다. 학습 자체는 외부 코드로 수행하며 [평가 기준·CLI·재학습 준비물](evaluation-policy.md)을 참고하세요.

평가 포함 건수와 누락 예측을 함께 확인합니다. 검수 항목이 없거나 TP/FP/FN이 모두 0이면 F1은 “—”로 표시합니다. 이전 집계에는 대표 F1을 복원할 정보가 없을 수 있으므로 실제 예측을 다시 가져오세요. 내부 기준을 회사 공식 지표 확정으로 보고하지 않으며 여러 split의 점수를 섞어 test 최종 성능처럼 표시하지 않습니다. Mock 결과에는 시험용임을 표시합니다.

## 8. 고급 기능과 오류

팀 ZIP 교환·충돌 처리, 평가, 데이터 품질·준비는 「평가 · 고급 기능」에 있습니다. 검수 ZIP에는 영상과 API Key가 없습니다. 프로젝트 백업은 DB를 포함하며 원본 영상은 별도 보관해야 합니다. 복원은 기존 프로젝트를 덮어쓰지 않습니다.

기본 화면의 오류는 한국어로 원인과 다음 행동을 안내합니다. 알려지지 않은 오류는 식별번호를 보여주고 원문은 상세 기록에서 확인합니다. 파일명·샘플 ID·모델명·내부 진단 코드까지 임의로 번역하지 않습니다. 지원 요청 시 키·계정 정보를 보내지 마세요.

## 9. 현재 제한

영역 bbox/mask 생성, IoU 계산, 회사 변화탐지 모델 직접 학습은 제공하지 않습니다. 분류 점수 계산 기능이 있다고 실제 목표 성능을 달성한 것은 아닙니다. 모의 데이터·오프라인 테스트와 실제 영상·실제 모델 검증을 구분하세요.
