# 회사 회신 전 내부 실험 계획 v1

2026-10-15. 사용자가 회사 회신을 기다리는 동안 자체 기준으로 진행하고, 답변을 받으면 기준을 조정하기로 결정했습니다. **회사 회신은 내부 개발·데이터 점검·평가 준비의 선행 조건이 아닙니다.** 기존 유료 API·회사 서버 접근·원본 수정 금지와 main 병합/릴리스 보류는 유지합니다.

## 이번에 고정하는 기준

| 항목 | 내부 기준 v1 |
| --- | --- |
| 먼저 입증할 것 | 앱으로 라벨을 검수·수정·내보낼 수 있는지, 실제 LLM 예측이 독립적인 사람 정답과 얼마나 일치하는지 |
| 대표 지표 | scene-f1-v1: arti/tree/fore/farm/water 중 하나라도 변화가 있으면 양성인 변화 유무 F1 |
| 보조 지표 | 주요 5개 라벨 micro F1, 라벨별 Precision/Recall/F1, FP/FN/TN/TP, 검수 수량·수정률·소요 시간·기록된 API 사용량 |
| 임시 목표 | 대표 F1 0.85 이상을 실험 목표로 삼되 보조 점수·오류 사례를 함께 보고. 현재 점수나 달성 약속이 아니며, 미달 결과도 그대로 기록 |
| 현재 기준 점수 | 미측정. 기존 모델 F1이 0.80이라고 가정하지 않음 |
| 입력 후보 | 제공 자료 전체. 손상·누락·중복·라벨 충돌·split 누출은 기존 품질 규칙 적용 |
| 개발 표본 | 기존 val의 고유 후보 최대 50건. 지침·프롬프트·UI 점검에 사용 |
| 평가 표본 | 기존 test의 고유 후보 최대 200건을 별도로 고정. 실제 정답과 예측이 갖춰져야 평가 가능 |
| 정답 | 영상을 직접 보고 사람이 판정·확정. Mock/원본 라벨 자동 승인은 정답 구축에 포함하지 않음 |
| 영문 사유 | 선택. 자동 유료 번역 추가하지 않음 |
| 재학습 | 코드·가중치·환경이 확보되면 같은 모델/설정·고정 test로 전후 비교. 확보 전에는 라벨 검수·LLM 품질 평가를 진행하고 실제 재학습 효과는 미측정으로 남김 |

0.85는 내부 목표를 정한 것이며 회사가 요구하는 F1/F2·대상·목표를 확정한 것이 아닙니다. 200건도 초기 실험 규모이며 통계적 충분성을 보증하지 않습니다. 후보가 부족하면 부족 수량을 기록하고 다른 split을 옮겨 채우지 않습니다. 유료 3,000건 본처리를 자동 시작하지 않습니다.

표본은 dataset/errors 출처·오류 폴더·원본 라벨 조합을 고려한 균형 추출입니다. FN/FP 폴더명은 출처 정보이며 정답으로 해석하지 않습니다. 이렇게 뽑은 표본의 비율은 전체 운영 데이터의 자연 분포와 다를 수 있으므로 전체 데이터의 F1로 일반화하지 않습니다. 실제 평가에는 포함/제외 건수·사람 정답의 양성/음성 비율·표본 선정 방식을 함께 보고합니다. 이미 프롬프트나 모델 개선에 사용한 영상은 test 평가에서 제외합니다.

## 실행 순서와 완료 기준

1. **프로그램 수용 확인 20건:** 이미 준비된 Mock 프로젝트를 사람이 직접 검수합니다. 저장 → 재실행 → 별도 JSON 내보내기 → 수정 라벨·사유·원본 보존을 확인합니다. 이 단계의 점수는 실제 LLM 성능으로 보고하지 않습니다.
2. **전체 자료 읽기 전용 점검:** Import·원본 해시 재검증·영상 내용 중복·split 누출·라벨 충돌을 집계합니다. 안전한 고유 후보에서 val 50건과 test 200건을 seed로 선정하고 데이터 지문·선정 ID·원본 해시를 로컬 manifest로 고정합니다. 선정은 사람 정답 확정을 뜻하지 않습니다.
3. **val 개발 표본 검수:** 검수 화면의 「독립 판정」을 켜서 원본/AI 예측을 보기 전에 영상으로 1차 판정하고 의심 사례를 재확인합니다. 준비된 초안은 원본 라벨 복사본이므로 일반 모드로 확정하면 독립 정답으로 보지 않습니다. Golden Set의 `blind_reviews`로 독립 판정 수를 함께 보고합니다. 같은 26.03.24 라벨 지침을 사용합니다. 사람 확정 수량·제외/보류 이유를 기록합니다. 실제 LLM 호출은 모델·예약 추정·학교 예산을 확인하고 별도 호출 지시를 받은 뒤 진행합니다. 호출 승인을 기다리는 동안 사람 정답·오류 사례·시연 준비는 계속할 수 있습니다.
4. **val에서 설정 결정:** 실제 LLM이 반환한 라벨을 사람 정답과 비교합니다. 프롬프트·모델을 바꾼 실험은 별도 Run으로 보존합니다. Mock은 연결·저장 시험에만 사용합니다. F1뿐 아니라 FN/FP와 라벨 유형 오류를 보고 설정을 결정합니다.
5. **test 평가:** val에서 선택한 설정과 프롬프트를 고정한 뒤, 개발에 사용하지 않은 test 정답·실제 예측으로 평가합니다. test를 보고 설정을 조정했다면 해당 세트는 개발에 사용된 것으로 기록하고 이후 독립 평가에는 재사용하지 않습니다. 같은 지역·촬영 구역의 유사 타일 누출은 자동 정확 중복 검사 외에 사람이 확인해야 합니다.
6. **정제 데이터와 시연 자료:** 원본을 보존하며 검수 JSON을 별도로 내보냅니다. 처리/완료/보류/수정 수량·측정 시간·실제 사용량·대표 수정 사례·남은 오류를 보고합니다. 회사 시스템 설치나 모델 재학습을 완료했다고 표시하지 않습니다.
7. **실제 재학습이 가능해지면:** 동일한 학습 코드에서 원본 train과 정제 train을 비교하되 val/test를 학습에 넣지 않습니다. 가중치·seed·설정·평가 정답을 기록하고 기존/재학습 모델 예측을 앱의 같은 Golden Set으로 가져와 변화량을 계산합니다. 개선하지 않으면 그 결과도 보존합니다.

## 서로 다른 성과를 구분

**프로그램 동작**, **실제 LLM의 라벨 정확도**, **검수 수정률**, **회사 모델 재학습 성능**은 각각 다른 결과입니다. 사람이 고친 라벨을 그 사람이 만든 정답과 비교해 100%가 된 것을 모델 개선 성과로 보고하지 않습니다. 원본 JSON과 사람 정답의 일치율을 계산하더라도 그것을 기존 회사 모델의 실제 추론 성능으로 부르지 않습니다. IoU·영역 주석·실제 회사 모델 실행은 별도 구현/입력이 필요한 범위입니다.

현재 제공 자료에는 회사 모델 학습 코드·가중치가 없습니다. 회사 회신 없이도 1~6의 준비와 검수는 진행할 수 있지만 실제 추론/API 단계에는 해당 모델/호출 권한이 필요합니다. 독자적인 새 학습 모델 구축은 현재 프로그램의 필수 범위로 추가하지 않습니다.

## 나중에 기준을 바꾸는 방법

- 라벨의 의미·양성 정의가 그대로이고 F1/F2 등 집계만 바뀌면 **보존한 실제 라벨 예측과 고정 정답**으로 다시 계산합니다. API 재호출이 항상 필요한 것은 아닙니다. 비용을 줄이기 위해 원래 예측 JSON도 로컬에 보관합니다.
- 라벨 의미·대상 데이터·정답이 달라지면 기준 v2와 새 Golden Set을 만듭니다. 기존 결과를 덮어쓰지 않습니다. 다른 기준의 점수를 그대로 전후 비교하지 않습니다.
- 회신 내용·변경 이유·적용 시점을 문서에 기록하고, 이미 수행한 실험을 소급해 공식 성과라고 바꾸지 않습니다.

## 지금 바로 할 일

개발자는 전체 후보 점검과 표본 manifest 준비를 진행하고, 사용자는 준비된 20건의 실제 영상 검수를 시작합니다. 이후 val 표본 정답 구축과 시연 자료를 준비합니다. 회사에는 추가로 문의할 수 있지만 회신을 내부 진행의 차단 조건으로 두지 않습니다.
