# 내부 평가 기준과 실제 실행 순서

2026-10-15 사용자 결정 반영. 회사가 확정한 공식 성과지표와 구분하는 **내부 작업 기준**입니다. 영문 사유는 필수가 아니며, 제공된 파일 전체를 후보로 사용할 수 있습니다. 유료 본처리와 회사 서버 접근은 이번 작업에 포함하지 않습니다.

## 점수 정의

대표 점수는 **영상 쌍 1건의 변화 유무 F1**입니다. 인공물(arti), 나무(tree), 산림(fore), 농경지(farm), 수계(water) 중 하나라도 1이면 변화 있음(양성), 모두 0이면 변화 없음(음성)입니다. 하위 인공물 라벨과 고정 0인 도로 표식은 대표 점수에 중복 합산하지 않습니다. 기준 식별자는 `scene-f1-v1`입니다.

| 구분 | 사람 정답 | 모델 예측 |
| --- | --- | --- |
| TP 정탐 | 변화 있음 | 변화 있음 |
| FP 오탐 | 변화 없음 | 변화 있음 |
| FN 미탐 | 변화 있음 | 변화 없음 |
| TN 정상 음성 | 변화 없음 | 변화 없음 |

`Precision = TP/(TP+FP)`, `Recall = TP/(TP+FN)`, `F1 = 2TP/(2TP+FP+FN)`입니다. TP·FP·FN이 모두 0이면 대표 F1은 정의할 수 없어 화면에 —로 표시하고 전후 변화량은 null로 저장합니다. 내부 숫자 호환을 위해 개별 집계의 f1=0과 defined=false를 함께 보존하므로 보고서를 읽는 코드도 defined를 확인해야 합니다.

보조 점수는 기존 **주요 5개 라벨의 micro F1**과 라벨별 Precision/Recall/F1/F2입니다. 변화는 맞혔지만 유형을 틀린 예측은 대표 점수에서는 맞고 보조 점수에서는 틀릴 수 있습니다. 따라서 대표 점수만으로 라벨 품질을 설명하지 않습니다. F2도 참고값으로 남깁니다.

## 정답과 데이터 분리

제공 파일 전체를 후보로 사용하되 손상·누락·파싱 실패를 통과시키거나 중복을 여러 건으로 세지 않습니다. 기존 train/val/test를 유지합니다. train은 학습, val은 설정 선택, test는 선택 완료 후 최종 비교에 씁니다. 동일 영상 누출은 앱이 검사하지만 같은 지역의 유사 타일·촬영 구역 중복은 사람이 추가 확인해야 합니다.

사람이 T1/T2를 보고 확정한 DONE 검수만 Golden Set으로 고정합니다. 평가용 정답은 원본·AI 라벨을 숨기는 「독립 판정」으로 만드는 것을 원칙으로 하며, Golden Set 메타데이터의 `blind_reviews`(독립 판정 건수)를 보고서에 함께 적습니다. 이 값은 기록 출처 표시이며 지문(fingerprint)에는 포함하지 않습니다. 원본 라벨을 복사하거나 Mock 결과를 자동 승인한 것을 실제 정답으로 보고하지 않습니다. 학습용 정제 데이터와 평가용 정답을 섞지 않습니다. 평가용 Golden Set은 val 또는 test 하나로 고정하며 중복·split 누출을 허용하지 않습니다.

공정한 전후 비교에는 **동일한 Golden Set**이 필요합니다. 정답 ID·지문·라벨 해시·스키마가 다르거나 예측이 빠지면 비교를 차단합니다. val·탐색용 결과는 참고 평가로 표시합니다. `final_test_eligible=true`는 evaluation/test라는 분류 표시일 뿐, 실제 모델이 test로 학습되지 않았다는 보증이나 공식 성과 승인이 아닙니다. test를 보고 설정을 조정했다면 새로운 독립 평가가 필요합니다.

## 자동 계산과 수동 확인

1. 검수 완료 → 「확정 검수를 기준으로 고정」 → 평가용 test를 선택합니다. 개발 중 비교는 val로 합니다.
2. 「예측 양식 받기」로 JSON을 받습니다. v2 양식의 null은 미입력입니다. 모든 라벨을 **실제 모델의 0/1 예측**으로 채우고 `prediction_status`를 `complete`로 변경합니다. 정답을 넣지 않습니다. golden_id·golden_fingerprint·evaluation_policy는 유지합니다. 기존 v1 예측 파일도 지원합니다.
3. 기존 모델과 재학습 모델의 예측을 각각 「모델 예측 가져오기」로 가져옵니다. 앱은 입력을 읽고 평가 결과를 프로젝트 DB에 추가하며 원본을 변경하지 않습니다.
4. 「전후 비교 · 보고서 저장」에서 기존/재학습 결과를 지정합니다. 대표 F1, 보조 점수, TP/FP/FN/TN 및 변화량 JSON과 사례별 CSV가 프로젝트 exports에 저장됩니다. 이전의 집계만 있는 평가는 대표 F1을 복원할 수 없으므로 실제 예측을 다시 가져와야 합니다.
5. CSV의 corrected(수정됨), regressed(새 오류), both_wrong(둘 다 오류) 사례를 영상과 대조하고 `manual_checked`, `manual_notes`에 직접 기록합니다. 정상 사례도 표본 확인하세요. **CSV를 출력한 것만으로 수동 검수가 끝나지 않습니다.**
6. 「수동 집계 대조」에 독립적으로 센 TP,FP,FN,TN을 입력해 자동 계산과 대조합니다. 이 기능은 숫자만 대조하며 정답·모델 예측을 변경하지 않습니다. CSV 수정사항은 DB로 자동 반영되지 않습니다. 정답을 고치면 새 Golden Set을 만들고 두 모델을 같은 새 정답으로 다시 평가합니다.

`delta_f1 = 재학습 F1 − 기존 F1`, `delta_percentage_points = delta_f1 × 100`입니다. 예를 들어 **설명용 가상 수치** 0.80 → 0.85는 +0.05, +5.0%p입니다. 상대 개선율 5%와 다릅니다. 이 숫자는 이번 프로젝트의 측정값이나 달성 목표가 아닙니다. 정답 수량·양성/음성 비율·평가 범위와 함께 보고하며 작은 표본의 상승만으로 전체 개선을 선언하지 않습니다.

CLI로 같은 계산을 자동화할 수도 있습니다. API 호출이나 학습 실행은 없습니다.

양식의 `inputs`는 sample_id별 logical_key·split·이미지 상대경로를 제공합니다. 이미지 경로는 Import한 데이터 루트 기준입니다. 이 목록으로 실제 추론 결과를 sample_id와 연결하며 정답 JSON 경로·정답 라벨은 제공하지 않습니다. 모델별 추론 코드는 각 모델 출력 형식을 이 예측 양식으로 변환해야 합니다.

```powershell
.venv\Scripts\python scripts/evaluate_models.py "C:\work\project" --baseline "C:\work\baseline.json" --retrained "C:\work\retrained.json"
```

## 재학습에 필요한 별도 입력

현재 제공 자료에는 학습 코드·가중치가 확인되지 않았습니다. 앱에 임의 모델이나 회사 서버 연결을 추가하지 않습니다. 실제 재학습을 자동 실행하려면 아래 정보가 필요합니다.

| 입력 | 필요한 내용 |
| --- | --- |
| 모델 코드·환경 | 저장소/로컬 경로, 의존성, GPU·메모리 요구 |
| 기존 모델 | 가중치 경로, 설정, 실제 baseline 예측 명령 |
| 학습 | 정제 train 입력 경로·라벨 형식, val 경로, 학습 명령·seed |
| 추론 | 고정 test의 각 sample_id에 대응하는 실제 0/1 라벨 예측과 변환 방법 |
| 기록 | 코드 커밋·가중치 해시·설정·seed·데이터 지문·실행 시간 |

실행 권한과 환경이 있는 사람이 수동으로 학습·추론한 뒤 예측 JSON만 가져와도 같은 평가가 가능합니다. 이 앱의 자동 계산은 회사 모델 재학습이나 영역 mask/bbox·IoU 평가 전체를 구현한 것이 아닙니다.

## 현재 미확정 사항

회사 회신을 내부 작업의 선행 조건으로 두지 않습니다. [내부 실험 계획 v1](independent-experiment-plan.md)에 따라 임시 목표와 개발/평가 표본을 정해 진행하고, 회신 후 기준을 버전으로 관리합니다.

공식 F1/F2·양성 정의·목표 수치, 평가 데이터 확정과 수행 주체, 최종 3,000건 선정·제출 범위·일정은 회사와 맞춰야 합니다. 사용자는 F1을 예상했으므로 내부 기준은 위와 같이 정했지만 회사의 공식 확정으로 기록하지 않습니다. 제공 파일 전체 사용 허용과 유료 3,000건 본처리 승인은 별개입니다. 영어 번역을 위한 자동 유료 호출은 추가하지 않습니다.
