# 인수인계 1~3번 수정 · 2026-10-15

기준 main은 0b63f14(PR #10), 마지막 릴리스는 v0.1.10입니다. 이 문서는 미배포 수정 브랜치의 기록입니다. 기존 AGENTS 지침을 모두 보존하고 다운로드한 추가 규칙과 HANDOFF를 병합했습니다. 회사 참고자료는 저장소 밖에 두었고 테스트에는 합성 이미지/JSON과 Mock·가짜 HTTP 응답만 사용합니다.

## 실제 수정

### 1. 해제한 기타 라벨의 설명

수정 전 effective_doc에서 arti_other=0으로 바꿔도 artifact_detail.arti_other_detail이 남는 것을 재현했습니다. 최종 문서 구성 시 해당 키가 있으면 빈 문자열로 비웁니다. 기타가 활성인 경우 설명을 보존하고, 키가 없으면 불필요하게 새 필드를 추가하지 않습니다. 원본 JSON 바이트·해시·검수 이력은 수정하지 않습니다. 검수 화면에도 최종 기타 설명을 표시합니다. 재실행·복원·내보내기도 같은 공통 함수를 사용합니다.

### 2. 낮은 신뢰도 검수

원본과 모두 0으로 일치하는 Mock 결과(confidence=0.1, review_required=false)가 core에서 필수 검수 0건/AUTO_KEEP로 처리됨을 재현했습니다. 이는 과거 v1 정책을 의도적으로 유지한 동작이었습니다.

| 작업 | 변경 후 동작 |
| --- | --- |
| 새 작업 기본 detailed | 불일치·AI 요청·낮은 신뢰도 모두 필수 검수 |
| 기존/명시 선택 core 시험용 | 이전 동작 보존. 낮은 신뢰도 단독은 자동 유지 가능하며 UI·Gate 보고서로 알림 |
| 본작업, 기존 core 포함 | 낮은 신뢰도는 항상 필수 검수 |

비교 재실행 전의 오래된 AUTO_KEEP 행에도 검수 목록·요약·통계에서 본작업 규칙을 적용합니다. 준비·내보내기 Gate는 실제 예측 신뢰도를 다시 확인하므로 이전 required=0만으로 통과할 수 없습니다. 완료 검수는 그대로 인정합니다. 원래 Run 설정·프롬프트·결과 해시와 검수 revision은 바꾸지 않습니다.

Gate 결과의 human_complete/total, all_human_reviewed 및 화면 안내로 사람 검수 범위를 구분합니다. Gate 통과는 전건 사람 검수 완료나 모델 정확도 향상을 뜻하지 않습니다.

### 3. API 비용 예약

수정 전 큰 영상 두 장도 20,000 입력 토큰만 예약하는 경로를 재현했습니다. 이제 전송할 두 영상의 실제 크기를 준비한 뒤 모델·detail별 영상 토큰, 프롬프트·사용자 지시·응답 스키마, 출력 한도로 예약합니다. 텍스트는 외부 토크나이저 다운로드 없이 UTF-8 바이트 수와 추가 여유분으로 보수적으로 추정합니다. 기존 input_token_reserve는 최소값으로 유지하고 계산량이 더 크면 늘립니다.

자동 영상 계산은 공식 문서에서 규칙을 확인한 gpt-4o-mini/gpt-4o/gpt-4.1에 한정합니다. gpt-6-luna/gpt-6.1-sol은 확인한 vision 표에서 토큰 규칙을 확정하지 못했으므로 다른 모델 공식을 임의로 적용하지 않습니다. 이 경우 이미지 1장 토큰 예약 추정치를 명시해야 하며 미입력은 API 전송 전에 중지합니다. 공식 근거: [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision), [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol). 문서 확인만 수행했으며 API 요청은 하지 않았습니다.

미확인 단가나 0원 OpenAI 설정은 허용하지 않습니다. 앱 단가는 기존 버전에 고정된 값이며 실시간 가격·청구서를 뜻하지 않습니다. 이미지 크기를 보지 않고 계산하던 전체 금액과 ‘예약 상한’ 문구는 요청별 추정 안내로 바꿨습니다. 수동 영상 예약과 텍스트 여유분도 실제 비용을 보장하지 않으며 계정·처리 등급·긴 컨텍스트 등 공급자 청구 조건은 별도 확인이 필요합니다.

요청 직전 쓰기 트랜잭션에서 누적 사용액 + RUNNING/UNKNOWN 예약액 + 이번 예약액을 검사합니다. 한도를 넘으면 요청과 attempt 생성 전에 멈춥니다. 각 재시도는 다시 예약하며 원격 결과 미확정 예약은 보존합니다. 실제 사용량이 확인된 성공/실패는 그 사용액을 기록하고 예약을 초과하면 일시정지합니다. 프로젝트 OS 잠금은 전송 중에도 유지하여 동시 worker의 중복 예산 소비를 막습니다. 예산은 작업별이며 다른 프로젝트·외부 프로그램까지 묶는 공급자 과금 한도가 아닙니다.

스키마 7의 job_reservation_events는 추정치·사유·시간을 추가 기록합니다. 자동 백업 후 마이그레이션하며 기존 설정을 덮어쓰지 않습니다. 「선택 작업 이미지 예약 변경」으로 추정치를 지정한 후 성공 결과를 유지하고 남은 작업을 재개할 수 있습니다. 로컬 사전 계산 실패만 대기로 복구하며 다른 실패의 재시도 규칙은 유지합니다. 구버전 앱으로 v7 DB를 열지 마세요.

## 테스트로 확인한 범위

- 수정 전 세 회귀 테스트 실패로 1~3번 재현.
- 기타 설명 제거, 활성 설명·알 수 없는 메타데이터 보존, 원본 바이트 불변.
- 합성 6건 Import → Mock 분석 → 비교 → 검수 저장 → 프로젝트 다시 열기 → JSON 내보내기. 백업/복원 후에도 같은 결과와 원본 해시 유지.
- 기본 낮은 신뢰도 검수 목록·남은 건수·Gate 차단, 기존 core 시험용 설정 해시와 동작 보존, 본작업 규칙과 완료 검수 인정.
- 본작업 검수 규칙 테스트는 6건 고정 결과에 대해 선정 수량 검증만 분리합니다. 3,000건 선정은 기존 독립 테스트가 담당하며 실제 유료 본처리를 실행한 것은 아닙니다.
- 공식 tile 계산 예, 모델/detail/크기·긴 프롬프트·스키마·출력량, 미확인 규칙/단가 차단, 예산 도달 전 무호출, 재시도 누적, 동시 실행 차단, 실제 사용량 초과 중지.
- 스키마 6 → 7 자동 백업, 설정 보존, 예약 변경 이력·충돌 검사, 같은 작업 재개, 백업 복원.
- Qt offscreen 검수 화면에서 체크박스와 최종 설명의 일치, Gate에서 사람 검수 범위 안내.

Windows / Python 3.11.17 / QT_QPA_PLATFORM=offscreen에서 전체 pytest 154개, Ruff 검사·포맷, compileall, Git index 비밀정보/데이터 검사, 자체 self-test(합성 6건·network_calls=0), GUI/worker smoke, 합성 UI 캡처를 통과했습니다. 전체 검사 후 검수 요약 조회가 전체 계획 JSON을 다시 읽지 않도록 최적화하고 관련 검사를 별도로 재실행했습니다. Windows 테스트에서 UTF-8 JSON을 시스템 기본 CP949로 읽던 부분도 명시적 UTF-8로 고쳤습니다. GitHub CI 결과는 PR 검증 기록을 함께 확인하세요.

제공된 회사 샘플 12개의 JSON 구조와 영상 크기(해당 표본 combined 336×166)를 읽기 전용으로 참고하고 읽기 전후 해시가 같음을 확인했습니다. 회사 자료를 테스트 fixture로 커밋하거나 실제 판정·검수 성과로 사용하지 않았습니다. 이번 전체 흐름 검증은 위 합성 6건입니다.
