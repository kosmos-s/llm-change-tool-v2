# 0.1.9 수정 정책과 실행 순서

## 선정 단위와 목표

`dataset_sample`에서 `dataset`과 `errors`를 함께 포함하는 부모 폴더를 가져온다. 좌·우 영상 쌍과 JSON 묶음이 샘플 1건이며, combined JPG는 비교용이다. 목표는 고유 샘플 3,000건이다. train/val/test 각 1,000건은 변경 가능한 기본 배분이며, 팀 합의 후 합계 3,000건 안에서 조정한다.

## 후보 정책 `unique-candidates-v2`

| 유형 | 처리 |
| --- | --- |
| 정확히 같은 영상·동일한 유효 라벨 | 논리 경로 정렬의 첫 항목을 대표로 선정. 모든 출처·오류 유형·구성원 ID 보존 |
| 동일 영상·라벨 불일치 | 충돌로 보류 |
| 중복 그룹의 누락·잘못된 라벨·부모/세부 라벨 모순 | 확인 전 보류 |
| 서로 다른 split의 동일 영상 | 누수로 보류. 자동 split 이동 없음 |
| 단일 샘플의 불완전 라벨 | 정제 후보로 유지하되 비교/최종 검증에서 필수 사람 검수 |
| 인공물 0·세부 라벨 누락 | 원본을 보존하고 내부 라벨만 0 정규화 |
| 이미지 누락·손상·JSON 파싱 실패 | FATAL / 해당 샘플 제외. 다른 안전한 후보의 작업은 허용 |
| JSON에 연결되지 않은 이미지 | 비연결 파일 경고. 선정 샘플이 아님 |
| 등록 원본의 바이트 변경·DB 라벨 불일치·계획 변경 | 작업 전체 차단 |

원본 JPG/JSON은 삭제·수정하지 않는다. 파일 SHA256은 변조 감지용으로 유지하고, 디코딩한 RGB 픽셀과 크기로 좌·우 영상의 정확한 일치를 검사한다. JPEG 메타데이터만 다르면 중복으로 묶인다. 재압축으로 픽셀이 달라진 이미지, 유사 이미지, 공간적으로 겹치는 타일은 이 검사에서 보장하지 않는다. pHash와 공간적 누수 검사는 별도 범위다.

좌·우 파일이 없는 combined-only 샘플은 combined 픽셀 기준으로 검사한다. 구분선 폭을 추정하지 않으므로 좌·우 그룹과 자동 교차 매칭하지 않는다.

FN/FP와 숫자 접미사는 원문 출처 정보이며 정답 라벨로 사용하지 않는다. 대표 선택은 라벨 일치 확인 후에만 수행한다. 충돌을 dataset 또는 errors 라벨로 자동 해결하지 않는다. 이번 버전에는 보류된 중복 그룹의 라벨/배치 결정을 원본 대신 저장하는 전용 해결 UI는 없으며, 본작업은 보류 그룹을 제외한 후보에서 진행한다.

등록 → 구조 유효 후보 → 고유 후보 → 보류/선정 가능 → 목표/부족 수를 split별로 표시한다. 사유 수는 겹칠 수 있지만 보류 총계는 한 번만 센다. split 간 중복 때문에 split별 고유 수의 합은 전체 고유 수와 다를 수 있다.

출처 집단은 dataset, errors, dataset+errors로 나누고, 집단을 먼저 균형 배분한 뒤 오류 유형·라벨 그룹을 순환한다. 부족한 집단의 잔여 할당량은 다른 집단으로 재배분한다. 고정 50:50이나 오류 폴더 수에 따른 출처 가중치를 사용하지 않는다. 시험용 새 작업은 출처 → split → 오류/라벨 순으로 균형 추출한다. 이 표본은 정제 대상이지 전체 모집단 성능을 대표하는 평가 표본은 아니다.

정책 버전·seed·목표·대표/구성원·보류/제외·선정 ID·분포는 새 계획에 고정하고 hash로 검증한다. Export manifest에 계획도 포함한다. 기존 계획·결과·검수를 덮어쓰거나 새 계획에 자동 재사용하지 않는다.

## 사용자가 할 일

1. 새 프로그램 압축을 새 폴더에 모두 푼다. EXE와 `_internal`을 함께 유지한다. 실행 화면의 버전이 0.1.9인지 확인한다.
2. 기존 프로그램을 종료하고 프로젝트 폴더를 백업한다. 새 버전으로 열 때 DB 스키마 5 전환 전 자동 백업도 만든다. 구버전 앱으로 업그레이드된 프로젝트를 열지 않는다.
3. 이번 점검은 새 프로젝트 `RISE-sample-v019-test`에서 시작해도 된다. 원본 `dataset_sample`과 프로젝트/출력 폴더는 겹치지 않게 한다.
4. 데이터·AI 작업 → 데이터 폴더 선택에서 dataset/errors의 부모 `dataset_sample`을 선택한다. 분할 압축 z01/z02/zip은 같은 폴더에서 모두 풀어 두어야 한다.
5. 본작업 모드 → 표본 미리보기에서 split별 등록/고유/보류/선정 가능/목표/부족을 확인한다. 부족 수가 있으면 계획 생성은 차단된다. 목표 배분을 팀과 조정하거나 범위를 넓히며 중복으로 채우지 않는다.
6. 시험용 모드, 표본 50건, seed 20260324, 공급자 Mock으로 작업을 생성한다. 실제 API는 호출하지 않는다. 분석 → 비교 → 이미지 표시 → 저장 → 종료/재실행 → 이어하기를 확인한다. Mock의 판정이 정답이라는 뜻은 아니다.
7. 실제 AI 시험은 새 시험용 작업에서 OpenAI를 선택하고 API Key·모델·예산·이미지 전송/유료 실행 동의를 확인한 후 50건을 실행한다. 표시 단가는 앱의 기록값이므로 실제 사용 모델의 현재 요금과 맞는지 확인한다.
8. 50건은 전부 이미지를 보며 검수한다. 변경 시 한국어 판단 근거를 입력하고, 최종 검증을 통과한 뒤 원본과 다른 폴더에 내보낸다. 파일 연결·최종 라벨·수량을 확인한다.
9. 팀이 split 배분을 확정하고 시험에 문제가 없으면 새 본작업 계획을 생성한다. 합계 3,000건을 고정하고 실행 중 표본을 다시 뽑지 않는다.
10. 본작업 처음에는 일부 진행 후 일시정지해 비용·성공·실패를 점검하고, 같은 작업의 이어하기로 나머지를 진행한다. 성공 결과는 재호출하지 않는다.
11. 분석 후 필수 검수·최종 라벨 검증·출력 검증을 완료한다. 처리 100%는 성공 100% 또는 납품 완료가 아니다. 회사 모델 재학습과 고정 평가셋 전후 비교는 별도 단계다.

## 실패와 재개

데이터 오류, API 인증/모델/결제 설정 오류, 일시 통신/서버 오류, AI 응답 오류, 원격 결과 미확정을 구분한다. 자동 재시도는 일시 오류에만 제한 횟수로 수행한다. 수동 일반 재시도는 재시도 가능한 실패만 대상으로 하고 성공·검수·이미 청구되거나 미확정인 비용을 보존한다.

인증/모델/결제 오류는 첫 실패에서 전체 일시정지한다. API Key·권한·결제를 수정했다면 복구 메뉴의 `인증·결제 수정 후 실패 복구`에서 수정 확인 후 해당 실패를 다시 대기로 준비한다. 고정된 모델명·프롬프트 자체를 바꾸려면 새 작업을 만든다. 원격 결과 미확정은 일반 재시도 대상이 아니며 원격 결과·과금 확인이 필요하다.
