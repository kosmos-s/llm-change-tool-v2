# 시험용 품질 검증 정책

데이터 가져오기는 원본을 수정하지 않고 품질 기록을 저장합니다. 작업 만들기에서 명시적으로 `시험용`을 선택해야 경고를 허용합니다. 폴더 이름으로 모드를 추론하지 않습니다.

| 검사 | pilot | production |
|---|---|---|
| 같은 split의 중복 / split 간 중복 | WARNING | FATAL |
| 원본 라벨 누락·잘못된 값·상하위 모순 | 필수 검수 | FATAL |
| 상위 0, 누락된 조건부 세부 라벨 | 내부 0 정규화 | 내부 0 정규화 |
| JSON 파싱 실패 / 실제 파일 누락 / 이미지 손상 | FATAL | FATAL |

상위 1의 누락 세부 값은 null(미확정)로 저장하며 검수 화면에서도 미확정으로 표시합니다. 판정과 한국어 근거를 확정하기 전에는 내보내기를 차단합니다. 원본 JSON bytes와 해시는 보존합니다. 정규화·수정 내용은 내보낸 복사본에만 적용합니다.

동일 검사 정책을 작업 생성, 실행, 재개 및 Final Gate에 적용합니다. pilot 내보내기 manifest에는 production=false와 WARNING 목록(중복 상대 경로 및 라벨 일치 여부 포함)을 기록합니다. 파일 무결성 검사는 모드에 관계없이 유지합니다.

이전 버전에서 일부 JSON이 거부된 프로젝트는 **새 프로젝트를 만든 뒤 동일 데이터 폴더를 다시 가져오세요**. 기존 검수 프로젝트는 삭제하지 마세요. 일부 샘플이 추가되면 fingerprint가 달라지므로 기존 실행에 자동 합치지 않습니다.

검증: 합성 데이터로 Import → pilot 작업 생성 → Mock 실행/재실행 → Compare → 검수 → Export. 동일 품질 문제는 production 차단, 손상·누락·파싱 오류는 두 모드 모두 차단. 실제 기업 sample 전체 및 유료 API 검증은 별도입니다.
